# 测试矩阵

每个模块一行。✅=已覆盖，—=不适用，❌=缺口（必须建 issue，不能默认接受）。

`pnpm test` 一次跑完三级（单元 + 集成 + E2E）。

| 模块 | 单元 | 集成 | E2E | 负责人 |
|---|---|---|---|---|
| 鉴权（登录、会话） | ✅ | ✅ | ✅ | — |
| 支付 / 计费 | ✅ | ✅ | ❌ | — |
| 工具函数（纯函数） | ✅ | — | — | — |
| 外部 API 客户端 | ✅（mock） | ❌ | — | — |
| 性能：观察器提取缓存 / 输入框不扫描、看板卡片复用 | — | ✅ | — | — |
## 如何保持真实

- 新行为必须在同一 PR 内新增一行（或扩展已有行）——没更新矩阵就不合入。
- ❌ 的行必须关联 issue；没有负责人的缺口就是谎言。
- E2E 可以薄，但必须覆盖那一条核心用户路径。
