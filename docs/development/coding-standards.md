# 编码规范

## 通用原则

- 代码被读的次数远多于被写的次数：为读者优化。
- 小而聚焦的变更胜过聪明的写法。
- 删掉死代码，不要注释掉。

- 公开函数必须有文档注释且至少有一个测试。
- 禁止无理由的 `any` / 非检查转换。
- 超过 300 行的 diff 必须拆分或事先评审。
## 命名与结构

- 命名说「是什么」不说「怎么做」：`calculateTax` 而不是 `doCalc2`。
- 一个文件一个概念；合理情况下单文件不超过约 400 行。
- 遵循 AGENTS.md 中的布局；新增顶层目录需要先写 ADR。
## 错误处理

- 在边界处大声失败，绝不静默吞掉错误（空的 `catch {}` 就是 bug）。
- 错误信息要说清：发生了什么、期望是什么、下一步做什么。
- 信任边界处做校验，内部用断言保证不变式。
## 常见坏味道（看到就改）

- 魔法数字/字符串：给它们命名（`const MAX_RETRY = 3`）。
- 复制粘贴的代码块：第三次出现时必须抽取。
- 做两件事的函数：拆开；好名字应该一口气念完。
- 复述代码的注释删掉，解释「为什么」的注释留下。
